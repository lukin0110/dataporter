# Graft — the repo's code graph for coding agents

[Graft](https://github.com/trailhq/Graft) (`@nanonets/graft`, MIT) indexes this repo into a
graph an agent can query instead of re-grepping the source on every task: prose nodes that
explain a subsystem, plus a per-symbol wiring graph of who calls what, each hit carrying an
exact `file:line`.

It is **development tooling only**. It has no part in the migration itself: nothing under
`src/dataporter/` imports it, no CLI command shells out to it, `make check` does not run it
and CI never installs it. Not having it installed costs you nothing but the graph.

## What is committed, and what is not

| Path | Committed | What it is |
| --- | --- | --- |
| `.claude/skills/graft/SKILL.md` | yes | Tells the agent to query the graph before grepping. Generated by `graft init`, ours to carry forward since the rename below. |
| `.claude/helpers/repo-graft-*.cjs` | yes | Shims Claude Code runs for the statusline and hooks. Both no-op silently when Graft is not installed. Renamed out of Graft's way — see below. |
| `.claude/helpers/ensure-graph.sh` | yes | Builds the graph when a checkout hasn't got one, and drops a stale wiring stamp. Ours, not `graft init`'s. |
| `.claude/settings.json` | yes | The `statusLine`, `hooks` and `permissions` blocks `graft init` merged in, since edited and now ours, plus one `SessionStart` entry of our own. |
| `tests/test_graft_wiring.py` | yes | Fails `make check` if any of this is silently rewritten. |
| `orca.yaml` | yes | Orca's worktree setup hook, which builds the graph before the first agent terminal opens. |
| `.mcp.json` | yes | Registers Graft's MCP server, exposing its six retrieval tools natively. |
| `.ignore` | yes | Keeps `graft/` greppable by ripgrep even though it is git-ignored. |
| `graft/` | **no** | The graph itself — a regenerable local cache, like `.venv/`. Git-ignored; build your own. |

The split is Graft's own: what you share is the wiring, and each person generates the graph
locally. That also keeps the graph out of review — it is derived from the source, so a stale
copy in a diff would only ever be noise.

## Using it

```bash
npm install -g @nanonets/graft   # once, or drop the -g and use npx
graft build                      # generate graft/ from the current tree
graft ask "where are seeds chunked?" --source
```

`graft build` is deterministic tree-sitter: no API key, no network, no model. Queries refresh
the graph against the working tree before answering, so an answer describes the code as it is
now, uncommitted edits included. `graft build --deep` adds LLM-written summaries and needs a
key for the provider you choose; nothing in this repo requires that pass.

## A fresh checkout has no graph

`graft/` is git-ignored, so a clone starts without it — and so does every Orca workspace,
each one a new git worktree. Graft's own session-start hook does not fill that gap: it reads
`graft/INDEX.md` to build the orientation block it injects, and with no file to read it emits
nothing. The first session would open blind, and the first `graft_*` call would query a graph
nobody built.

`.claude/helpers/ensure-graph.sh` closes it. It builds when `graft/INDEX.md` is missing and
returns instantly when it is there, so it is free to call on every session, and it never exits
non-zero — a missing Graft costs you the graph, not the run. Two things call it:

- **`orca.yaml`**, Orca's setup hook, run once when a workspace is created, beside
  `make install` for the same reason: `.venv/` is git-ignored too, and a fresh worktree has
  neither. `setupAgentStartupPolicy: wait-for-setup` makes the first agent terminal wait for
  it, which is the whole point — the session that opens has both the graph and the
  orientation.
- **A `SessionStart` hook in `.claude/settings.json`**, for a checkout Orca never made. It
  blocks the session start that builds, and only that one.

Neither is Graft's own wiring, and since the rename below neither is reachable by it.

## Graft rewrites this wiring on its own, and the filenames are the off switch

`graft init --agents claude --no-global` generated the shims, the skill, the `settings.json`
blocks and the `.mcp.json` entry. Four things were then changed by hand — and were silently
reverted three times, because the wiring refreshes itself without anyone running a command.

**The mechanism.** `reconcileWiring` (`dist/upkeep.js:240` in the installed package) rewrites
every file Graft believes it owns whenever the stamp at `graft/.cache/wiring-stamp.json`
disagrees with the running binary. Two callers, and neither is `init`: Graft's own session-start
hook (`dist/claude/hooks.js:413`) and MCP server boot (`dist/mcp/server.js:74`). Both run at the
start of every session, so the rewrite lands on the first upgrade and in every fresh clone —
the stamp lives under the git-ignored `graft/`, so a new checkout and every Orca worktree start
without one. A missing stamp also defaults to `{ global: true }`, which is how a repo wired
`--no-global` came to write `~/.claude/helpers/graft-hooks.cjs` and five hook entries into
`~/.claude/settings.json`: machine-wide, outside the repo, and firing a second copy of every
Graft hook in this one. Delete both if they reappear.

An earlier version of this page blamed "a plain re-run of `init`", which is why the reverts went
unnoticed for so long: nobody ran `init`, so nobody looked.

**The off switch.** `wiredHostIds` (`dist/upkeep.js:211`) decides this repo is Claude-wired by
testing one exact path — `.claude/helpers/graft-hooks.cjs` — and `claude` is not in Graft's host
registry, so no other file can vote it back in. The shims are therefore committed as
`repo-graft-hooks.cjs` and `repo-graft-statusline.cjs`. With no host detected the refresh reaches
`if (hosts.length === 0) return null` and writes nothing, on any version, in any clone. The
substring `graft-hooks.cjs` stays inside the new names on purpose: `dist/claude/hooks.js:95`
reads the timeout a hook is running under by matching the command string against it.

One thing the rename does not cover: the refresh unions the stamp's hosts with what it finds on
disk, so a stamp written before the rename still says `claude`. `ensure-graph.sh` deletes such a
stamp at session start, and `tests/test_graft_wiring.py` fails `make check` if a graft-named shim
ever comes back.

## The four local edits, and why each one is there

They now survive on their own; the test pins them so a rewrite is loud rather than silent.

- **`const BAKED` in both shims is blank.** The wiring pass bakes in the absolute path of
  whichever install it ran from — an npx cache, or one Node version's global `lib` — and that
  path exists on exactly one machine. The shims already resolve a project-local, node-local or
  globally installed Graft on their own; the baked path only ever misses for everyone else.
- **`.mcp.json` invokes `npx -y @nanonets/graft mcp`, not a bare `graft`.** This repo has no
  Node toolchain of its own, so a global install is not a safe assumption to bury in a
  committed config — the bare form is what produced `Executable not found in $PATH: graft`
  here. `npx` uses the global install when there is one and fetches the package when there is
  not. It is the form Graft's own README gives for registering by hand.
- **The Bash allowlist is cut to the two commands this repo actually runs**, `graft:*` and
  `npx -y @nanonets/graft:*`. The refresh also pre-approves `npx graft:*`, `graft-dev:*` and
  `node dist/cli.js:*`. The first is not this package at all — `graft` on npm is an unrelated
  *"Full-Stack JavaScript Through Microservices"* library, and `npx graft …` would fetch and
  run it. The other two are the aliases Graft uses when developing Graft itself (`dist/cli.js`
  is its own `bin` entry); there is no `dist/` here, so they only widen what runs unprompted.
  Raised by Copilot in review on #12.
- **The shims are renamed**, which is the edit that keeps the other three.

## Adopting a newer Graft's wiring

The cost of the off switch is that a new version's skill text, shim resolution and hook timeouts
no longer arrive on their own. Take them deliberately, in a diff you can read:

```bash
git worktree add /tmp/graft-wiring HEAD
cd /tmp/graft-wiring && graft init --agents claude --no-global --no-build
diff -u "$OLDPWD/.claude/helpers/repo-graft-hooks.cjs" .claude/helpers/graft-hooks.cjs
diff -u "$OLDPWD/.claude/skills/graft/SKILL.md"       .claude/skills/graft/SKILL.md
```

Port what is worth porting into the `repo-`named files, keep `BAKED` blank, then
`git worktree remove /tmp/graft-wiring`. Nothing about the upgrade touches this checkout, which
is the point: the wiring changes when you decide it does.
